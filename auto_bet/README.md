# auto_bet — v24 の買い目をテレボートに自動投票する

`history.json`（GitHub Actions の v24 が push しているもの）を2分おきに読み、
締切まで25分以内のレースの買い目を Chrome で投票します。Windows のご自身のPCで動かします。

**予想側（GitHub Actions / v24）はいっさい触りません。`history.json` を読むだけです。**
書き込むと予想側の push と衝突して記録が壊れるので、このフォルダからは書きません。

**通知された組を、そのまま買います。** 投票の時点でオッズを見直して買う買わないを
決め直すことはしません。v24 は通知した時点の判断で買う前提で検証されているので、
投票時に再判定すると検証していない別のルールになり、成績が何を意味するのか
分からなくなります。

---

## 最初にすること（順番どおりに）

### 1. 入れる

```
pip install playwright
playwright install chromium
```

`use_installed_chrome: true`（既定）なら、お使いの Chrome がそのまま使われます。

### 2. テレボートのURLを書く

`config.json` の `telebote_url` が空です。テレボートのURLをご自身で確認して入れてください。

### 3. 画面のセレクタを採取する（ここだけは私には書けません）

```
playwright codegen --channel=chrome <テレボートのURL>
```

1. `codegen` を起動する
2. 手でログインする
3. 適当なレースで **100円ぶんの舟券を実際に1つ買ってみる**（3連単1点）
4. 出てきたコードから、`telebote_page.py` の `SELECTORS` に写す

これで「場を選ぶ→レースを選ぶ→3連単を選ぶ→組を入れる→金額を入れる→投票→確認」が
全部そろいます。金額欄が口数（100円＝1口）なら `AMOUNT_IN_UNITS = True` にしてください。

埋まっていない項目があると、`dry` / `live` は**動き出す前に**止まり、どれが空かを言います。
`logged_in_mark`（ログイン済みのときだけ出ている要素）も入れておくと、
セッションが切れているのに空回りするのを起動時に止められます。任意です。

### 4. ログインのしかた

**テレボートは Chrome を閉じるとログインが切れます。**
そのため「先にログインしておく」ことはできません。`dry` / `live` を動かすと
Chrome が開いて、**最初にログインを聞かれます**。そこで手でログインして Enter。
あとはその Chrome を開いたまま放っておきます。

```
python auto_bet.py --mode dry
  → Chrome が開く → 手でログイン → 黒い画面で Enter → あとは自動
```

**加入者番号・暗証番号はどこにも保存しません。**
`chrome_profile/` には「加入者番号を保持」などの設定だけが残ります。
`.gitignore` に入れてありますが、**絶対に共有しないこと。**

動いている途中でログアウトさせられたときも、同じように聞きます
（画面から入力できない状態＝無人で動かしているときは、止まります）。

`--mode login` も残してありますが、上のとおりログイン状態は持ち越せないので、
ふだんは使いません。

## 4つのモード

| モード | 何をするか |
|---|---|
| `login` | Chrome を開いて止まる。手でログインする |
| `check` | ブラウザを開かず、いま買うべきレースを一覧表示するだけ |
| `dry` | ブラウザを開き、確認画面まで進んで**押さない**（スクショを `shots/` に保存） |
| `live` | 実際に投票する |

**既定のモードはありません。`--mode` は毎回自分で書きます。**

`live` は `config.json` の `i_have_read_the_terms` が `true` のときだけ起動します。
これは「テレボートの『電話投票に関する約定』を自分で読んで、自動操作について
問題ないと判断した」という**あなた自身の記録**です。`run.bat` の `7)` の中の
`1) live を使う` から、`yes` と打てば立てられます（戻すのも同じところ）。

```
python auto_bet.py --mode check
python auto_bet.py --mode dry
python auto_bet.py --mode live
python auto_bet.py --mode check --once     1周だけ
```

### `run.bat`（いちばん簡単）

**`run.bat` をダブルクリックして、番号を押すだけ**です。コマンドを打つ必要はありません。

```
 1) check   いま買うべきレースを見るだけ（ブラウザ無し）
 2) dry     ブラウザを開き、確認画面まで進んで押さない
 3) live    実際に投票する（y を入れて確認してから動きます）
 4) ためす   疑似の買い目で dry を試す（買い目が無い日用）
 7) 金額や上限の設定を変える
 8) ログの最後の30行を見る
 9) テスト
 0) 終わる
```

Ctrl+C で止めると、またメニューに戻ります。

デスクトップから開きたいときは、`run.bat` を右クリック →「送る」→
「デスクトップ (ショートカットを作成)」。

（`run.bat` の中身だけは Shift_JIS で保存してあります。Windows のバッチは
UTF-8 の日本語を読めないためです。編集するときは文字コードにご注意を）

### 買い目が無い日に試す

v24 の買い目は1日数レースしか出ないので、画面操作を試したいときに買い目が
無いことがあります。そのときは**疑似の買い目**を作れます。

```
python auto_bet.py --mode dry --fake 17-3        宮島3R、組は 1-2-3
python auto_bet.py --mode dry --fake 宮島-3      同じ
python auto_bet.py --mode dry --fake 宮島-3-2-1-4  組も指定する
```

締切は10分後ということにするので、そのまま「買うべき」に入ります。
**いま発売中のレース**を指定してください（テレボートのトップで確認できます）。

`run.bat` の `4) ためす` からも同じことができます。

**`live` では使えません。** 疑似の買い目は v24 が選んだものではないので、
実際のお金は使いません。

### 上げていく順番

いきなり `live` にしないこと。

1. **`check` を1週間** — 「いま買うべき」の判定が history.json と合っているか目で確認
2. **`dry` を1週間** — 画面が最後まで正しく進むか。`shots/` の確認画面を毎回見る
3. **`live` で1日1レースだけ** — `max_yen_per_day` を100にして1点だけ通す
4. 上限を少しずつ上げる

## 設定（config.json）

| 項目 | 意味 |
|---|---|
| `i_have_read_the_terms` | `true` にするまで `live` は起動しない。約定を読んだ記録 |
| `bet_yen` | 1点あたり（100固定でよい） |
| `max_yen_per_day` | 1日の上限（円）。`null` で無制限 |
| `max_points_per_race` | 1レースの上限点数。`null` で無制限。超えたらそのレースごと見送り |
| `buy_obi` / `buy_ana` | 帯（本番）／穴側（試験）。穴側は既定でオフ |
| `close_min_minutes` / `close_max_minutes` | 締切までこの範囲のレースだけ投票する（既定 0〜25分）。`close` はネット締切より3分早い値なので下限は 0 でよい |
| `poll_seconds` | 何秒おきに history.json を取りに行くか（既定120） |

これらは `run.bat` の **`7) 金額や上限の設定を変える`** から変えられます
（`config.json` を直接開いても構いません）。おかしな値は保存されません。

上限は使いすぎ防止ではなく**バグ避け**です。ループが暴走したり二重投票の判定が
壊れたときに、残高を一度に溶かさないための保険。最初は残高より少し下に置いて、
慣れたら `null` にする、という使い方を想定しています。
1日の使用額は `bet_done.json` の当日分から数えます。

実測の点数は 帯が最大2点、穴側が最大3点。4点以上が来たら異常なので、
既定の `max_points_per_race: 4` はそのレースごと見送って警告を出します。

## 止め方

- フォルダに `STOP` という名前のファイルを作る → 次の周で終わります
- Ctrl+C → その場で終わります。記録は投票のたびに書いているので壊れません

## 二重投票について

いちばん怖い事故なので、ここだけ念入りに作ってあります。

- 投票キーは `日付-場コード-R-組-種別`（例 `20260918-24-9-2-1-4-帯`）
- 同じレースが `picks` と `ana` の両方に出ることはあります。帯と穴側は別勘定なので、
  レース単位では重複排除しません（キーに種別が入っているのはそのため）
- 投票が成功したら、その場で即 `bet_done.json` に書きます（まとめて最後に書きません）
- 書き込みは一時ファイル → `os.replace` で原子的に
- `bet_done.json` が壊れていたら**空で続行せず、起動しません**（終了コード3）。
  中身を直すか、退避してから動かしてください
- 投票の確認画面で **場・R・勝式(3連単)・組・金額・合計ベット数・合計金額**を
  コードで読み返して照合し、一致しなければ押さずに中止します。これが最後の砦です。
  1点ずつ買うので確認画面はいつも「合計ベット数 1ベット」のはずで、
  **ベットリストに前の周の買い残りが混ざっていれば、ここで気づいて止まります**
- **余計な操作はしません。** 場を選べば締切のいちばん近いレースが開き、勝式も
  3連単が選ばれているので、そこは触りません。触る手が増えるほど事故が増えるためです。
  開いたのが目当てのレースでなかったときだけ、レース選択から選び直します
  （着いたかどうかは URL の `jyoCode` / `raceNo` で確かめます）
- テレボートは「一定時間操作がない場合、自動的にログアウト」します。
  買い目が無い時間が5分続いたら、**トップの「開催情報更新」を押します**
  （ページを開き直すよりログイン状態に触りません）。
  それでも切れていたら、Chrome で手でログインし直すよう聞きます。
  `config.json` の `keepalive_minutes` で間隔を変えられます（`0` で何もしない）
- 選んでから押すまでに時間が経つので、押す直前に締切をもう一度見ます。
  `close_min_minutes` を下回っていたらその組は見送ります
- 画面操作の途中で例外が出たら、**その周で打ち切って次のレースへ進みません**。
  画面が中途半端なまま次を操作すると、違うレースに投票する事故になるためです。
  ログに「★手で確認してください」と出るので、そのときは画面を見てください
- **投票を押した後で失敗したとき**（通ったかどうか分からないとき）は、
  投票済みとして記録したうえで**動作を止めます**（終了コード4）。
  次の周で「まだ買っていない」と見なして買い直すのがいちばん危ないからです。
  買えていなかった場合は1点買い逃すだけで済みます。
  テレボートの投票履歴を見て確認し、買えていなければ `bet_done.json` から
  その行（`note` に「要確認」と入っています）を消してください

### 終了コード

| | |
|---|---|
| 0 | 正常（STOP / Ctrl+C を含む） |
| 2 | 設定や準備が足りない（約定フラグ、URL、セレクタ、ログイン切れ、playwright 未導入） |
| 3 | `bet_done.json` が壊れている |
| 4 | **投票を押した後で分からなくなった。投票履歴を見て確認すること** |

## 動いているかどうか

買い目が無い時間帯でも、2分ごとに1行出ます。これが出ていれば生きています。

```
2026-09-19 10:12:03	check	-	-	-	-	-	見た	今日 帯7 レース / いま投票できる組 0件 / 次は 大村9R 帯 締切15:00（あと288分）
```

**画面が止まって見えるときは、黒い画面の中をクリックしていないか確認してください。**
Windows のコマンドプロンプトは画面内をクリックすると選択モードに入り、
タイトルバーに「選択」と出て**プログラムが本当に一時停止します**。Esc か Enter で再開します。
（プロパティ →「簡易編集モード」のチェックを外しておくと、そもそも起きません）

## ログ

`logs/auto_bet.log` に1行1イベントで追記します（タブ区切り）。

```
時刻 / モード / 場・R / 種別 / 組 / 点数 / 金額 / 結果 / 備考
2026-09-18 14:50:02	live	大村9R	帯	2-1-4	1点	100円	投票した	締切15:00(あと10分) 当日計 100円
```

python run_tests.py

締切2分前は選ばれない・10分前は選ばれる・30分前は選ばれない、すでに `bet_done.json` に
ある組は選ばれない、1日の上限に達していたら何も選ばれない、`ana` キーが無い日・

`bet_done.json` が壊れていたら起動しないこと、などを見ています。
画面操作は偽のページを差し込んで本体のロジックだけ回しています。

## Windows で動かすときの注意

- **PCが起きていないと動きません。** 対象は 8:00〜23:05。電源オプションでスリープを無効に。
  ノートなら蓋を閉じても動く設定に
- タスクスケジューラで朝に起動、深夜に終了、が扱いやすい
- 文字化けするなら `chcp 65001` を先に（`run.bat` はやっています）
- ウイルス対策ソフトが Playwright の Chrome 起動を止めることがあります。除外設定を
- **PC の時計とタイムゾーンが JST であること。**「時刻を自動的に設定する」がオンか確認を
  （時刻の計算は +09:00 固定で持っているので、絶対時刻さえ合っていれば狂いません）

## 動かないように見えるとき

- **通知が来たのに投票しない**：`raw.githubusercontent.com` は最大5分ほどキャッシュされます。
  毎回変わるクエリを付けていますが、それでも数分遅れることがあり、
  締切ぎりぎりのレースは取り逃します。予想側の push 自体が遅れることもあります
  （v24 のログに「push できず(次周に持ち越し)」と出る）。仕組み上の限界で、
  実害は「たまに買えない」だけ。買いすぎる方には転びません
- **何も選ばれない**：締切まで25分以内の買い目が無いだけ。買い目ゼロは正常な状態です

## 承知しておくこと

自動化する価値があるかは、まだ確定していません。

| | 検証値 | 的中数 | 注意 |
|---|---|---|---|
| 帯（本番） | 100.6% | 353本 | **ほぼトントン**。確定オッズでの値なので実運用は下がる |
| 穴側（試験） | 153.6% | 73本 | 2026年2〜8月に集中。10か月離れた2025/04では93.6% |

**帯だけを自動化しても期待値はほぼゼロです。** まず帯だけで `dry` を回して仕組みを確かめ、
`live` にするのは穴側の影の記録が半年ぶん貯まって数字が保った後、が正しい順番です。

テレボートの『電話投票に関する約定』は改定されます。**長く運用するなら、ときどき読み直して
ください。** `i_have_read_the_terms` は、そのつど自分で確認したという記録です。
